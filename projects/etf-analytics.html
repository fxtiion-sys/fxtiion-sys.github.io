What

A Python pipeline that downloads daily prices for five Canadian and US ETFs plus the Bank of Canada USD/CAD rate. It stores them in SQLite with incremental updates, validates the data, computes return and risk metrics, and builds a Markdown report with charts. A GitHub Actions workflow refreshes everything every weekday, and a read-only FastAPI service serves the results as JSON.

Why I designed it this way

  • Idempotent writes. Prices are upserted on a (date, symbol) primary key inside a transaction, with a CHECK (value > 0) constraint. Re-running an update never duplicates rows, and a failed batch writes nothing.
  • Detect rewritten history. Yahoo recalculates adjusted prices back through history when a fund pays a dividend. Each update compares the overlapping days with stored values, and if they differ by more than 0.01% it downloads the full history again instead of appending to differently scaled data.
  • No fake data on holidays. The TSX and NYSE close on different holidays. I keep only days when both were open and the Bank of Canada published a rate. Forward-filling would create fake 0% days and distort volatility and correlation.
  • Validate before analysing. The pipeline stops and lists every problem if it finds a spike, a frozen price, a long gap, a weekend row or a large Bank of Canada vs Yahoo FX gap. Thresholds sit just above the largest real values, so real market moves pass and data errors don't.
  • One job per component. The API only reads the database. If it's empty, it returns 503 instead of starting a download, so fetching stays the job of fetch.

  • The tracking-error drop showed that most of the earlier gap between VFV and SPY was noise in the exchange rate, not a difference between the funds.
  • The weekend row was being counted as a day when both markets were closed. Weekend rows are now dropped when the data is loaded.

What I learned

  • External data isn't clean just because it comes from a big provider. A single Saturday row in Yahoo's currency feed was quietly being counted as a market holiday. Now I write the checks before the analysis, not after something looks wrong.
  • The measurement can be the problem. I first read the gap between VFV and SPY as a difference between the funds. Changing only the exchange-rate source cut tracking error from 8.6% to 3.6%, so most of it was noise in how I measured.
  • Idempotent writes are what make automation safe. Because every update is an upsert inside a transaction, a scheduled job can fail halfway and simply run again with no manual cleanup.
  • Tests shouldn't depend on the network. Building tests on small, hand-computable price series and recorded API responses kept CI fast and deterministic.
