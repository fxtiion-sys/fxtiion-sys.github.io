What I built

This is a team project, so this page covers only my part, taken from my commits.

  • Project skeleton. The Flask JSON API and React (Vite) frontend setup the rest of the team builds on.
  • Data models. PostgreSQL models for users, rides and ride requests, the first migration, and an ERD kept in sync with the models.
  • Auth API. Sign-up, email verification, resend, login, logout and /me, with session login through Flask-Login. Every error goes through one helper that returns an HTTP status plus a machine-readable code such as EMAIL_TAKEN or INVALID_EMAIL_DOMAIN.
  • Frontend base. Routes, the bottom nav, design tokens and shared components, then the sign-up, check-email, login, Explore and Ride details pages, connected to the auth API with an auth context and protected routes.

Why I designed it this way

  • School-email-only sign-up. The app is meant for verified students only, so sign-up checks the email domain, and login is refused with 403 EMAIL_NOT_VERIFIED until the email link has been opened.
  • No account enumeration. "Resend verification" gives the same answer whether or not the account exists, so nobody can use it to check which emails are registered.
  • The verify link redirects instead of returning JSON. It's opened from an email in a browser, not called by the frontend, so it sends the student to the login page with the result in the URL.
  • Signed tokens instead of a token table. The verification link carries the user ID signed with the app's secret key and a purpose-specific salt, and it expires after a set time. There's no extra table to store or clean up. The tradeoff is that a link can't be revoked early, only expire, which is acceptable here because opening a verify link twice does nothing harmful.

What I learned

  • On a team, the foundation is a deliverable. Setting up the skeleton, data models and shared components early meant teammates could build pages and features in parallel instead of waiting on setup.
  • Docs only help if they match the code. I updated the ERD as soon as the models changed, so teammates could trust the docs instead of reading migrations.
  • Auth details are security details. Choices like time-limited signed links and giving the same answer whether an account exists or not decide what an attacker can learn.
  • Working through pull requests. Each piece of my work went into the shared repo as its own pull request (project setup, models, auth API, pages), which kept changes small and easy to trace.
